# ⚡ Поток 1: Инициализация и Холодный Старт Приложения

## Диаграмма Последовательности (Sequence Diagram)

```mermaid
sequenceDiagram
    autonumber
    actor Student as Студент
    participant TMA as Telegram WebApp SDK
    participant App as App.tsx (React 19)
    participant LS as LocalStorage (Кэш)
    participant CF as Cloudflare Worker
    participant DB as ExtendsClass JSON Bin

    Student->>TMA: Открытие приложения в Telegram
    TMA->>App: Инициализация WebView
    App->>TMA: WebApp.expand(), синхронизация цветов темы
    App->>LS: Чтение 'selectedGroup', 'customSchedule'
    LS-->>App: Возврат закэшированных данных (0 мс)
    App-->>Student: МГНОВЕННЫЙ РЕНДЕР РАСПИСАНИЯ (UI готов)
    
    Note over App,CF: Фоновая проверка обновлений (Stale-While-Revalidate)
    App->>CF: GET /sync/:binId (фоновый асинхронный запрос)
    CF->>DB: Запрос актуального JSON корзины
    DB-->>CF: Возврат данных с таймштампом
    CF-->>App: Ответ (200 OK + payload)
    
    alt Если есть новые изменения от старосты
        App->>App: Мягкое слияние mergeSchedules()
        App->>LS: Обновление локального кэша
        App-->>Student: Бесшовное обновление карточек пар (без сброса скролла)
    else Данные идентичны
        App->>App: Завершение без перерисовки
    end
```

## Подробный разбор шагов
1. **Запуск**: Студент кликает по ссылке или кнопке бота в Telegram.
2. **Инициализация SDK**: React проверяет глобальный объект `window.Telegram.WebApp`, раскрывает приложение на 100% высоты экрана и устанавливает безопасные отступы.
3. **Чтение кэша**: Синхронный запрос к `localStorage` возвращает расписание группы. Экран отрисовывается за 0 миллисекунд.
4. **Фоновый синк**: В фоновом режиме уходит запрос к [[cloudflare-worker.js - Пограничный Шлюз]]. Если староста внес правки, они мягко встраиваются в интерфейс.
