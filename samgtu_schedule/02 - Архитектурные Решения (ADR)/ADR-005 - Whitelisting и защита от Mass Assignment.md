# 📜 ADR-005: Whitelisting входящих DTO и защита от Mass Assignment

## 1. Контекст и Проблема
Поскольку клиенты отправляют изменения расписания в облако через Cloudflare Worker, существовала опасность инъекций и внедрения посторонних данных:
* Злоумышленник мог отправить в JSON системные поля (`isAdmin: true`, `role: "superadmin"`).
* Внедрение прототипного загрязнения (`__proto__`, `constructor`).
* Перегрузка хранилища мусорными гигантскими пейлоадами (DoS по объему данных).

## 2. Принятое решение
В [[cloudflare-worker.js - Пограничный Шлюз]] внедрен строгий механизм белого списка полей (**Whitelisting DTO Sanitizer**):
1. Сервер парсит входящий JSON и конструирует **новый чистый объект**.
2. В чистый объект копируются **исключительно** разрешенные поля:
   - `customSchedule` — массив валидных уроков.
   - `homework` — массив задач.
   - `updatedAt` — таймштамп обновления.
   - `checksum` — контрольная сумма.
3. Все остальные поля без исключения отбрасываются.
4. Введен жесткий лимит на размер тела запроса (не более 512 КБ).

## 3. Последствия
* **Положительные**: Невозможность внедрить посторонние поля или взломать ролевую модель через подделку сетевого запроса.
* **Отрицательные**: При добавлении нового поля в структуру расписания его необходимо явно прописать в белый список Cloudflare Worker.
