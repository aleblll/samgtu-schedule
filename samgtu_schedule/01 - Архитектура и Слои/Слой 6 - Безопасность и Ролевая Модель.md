# 🔒 Слой 6: Безопасность и Ролевая Модель

## 1. Что это такое
Система разграничения прав доступа гарантирует, что обычные студенты не могут подделать или стереть расписание группы, а старосты имеют доступ только к редактированию своей учебной группы.

## 2. Где расположено в кодовой базе
* `utils/auth.ts` — сервис проверки PIN-кодов, вычисление криптографических хэшей.
* `components/AdminPanel.tsx` — интерфейс администратора.
* `components/EditLessonModal.tsx` — проверка прав на сохранение изменений.

## 3. Ролевая модель
| Роль | Права | Способ авторизации |
|---|---|---|
| **student** (Студент) | Просмотр расписания, личные заметки, локальная посещаемость | По умолчанию (без пароля) |
| **starosta** (Староста) | Редактирование расписания группы, отмена занятий, перенос аудиторий, синхронизация с облаком | Ввод 4-6 значного PIN-кода группы |
| **admin** (Администратор) | Полный доступ ко всем группам, сырым системным логам, импорту расписания | Мастер-PIN администратора |

## 4. Механизм защиты
* **Web Crypto API**:
  PIN-коды никогда не сохраняются в открытом виде. При вводе PIN-кода вычисляется его хэш:
  ```typescript
  const hashBuffer = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(pin));
  ```
  Сверяется только полученный хэш. Даже если злоумышленник проанализирует исходный код клиента, он увидит только хэш-строку, восстановить пароль из которой математически невозможно.
* **Изоляция административной консоли**:
  Вход в скрытую консоль диагностики защищен секретной комбинацией: 5 быстрых тапов по логотипу приложения с последующей проверкой админ-хэша.
